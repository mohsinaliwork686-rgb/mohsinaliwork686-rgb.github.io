  • StackExchange.Redis

    Fixed a bug in StackExchange.Redis, the most widely used Redis client for .NET: commands sent in a batch never showed up in its profiler. Merged.

    Details
    • Batches skipped the one place where profiling was switched on. Moved that step into a method both paths share, so they cannot drift apart again. The issue had been open since 2022.
    • Reproduced it first, then added a test that fails without the fix and passes with it, and ran every other test that uses batches. A maintainer approved it within half an hour and merged it the same day, and it shipped in release 3.4.29.
    • Also reviewed the maintainer's own fix for an IPv6 parsing bug and found a place it missed, where a server's new address would silently vanish. The maintainer fixed it, with tests, before merging.

  • Swashbuckle.AspNetCore

    Fixed five bugs in Swashbuckle, the Swagger and OpenAPI library for ASP.NET Core: two crashes with inheritance turned on, two kinds of set documented without their rule, and filter edits that piled up on every request, a bug open since 2020. All five merged; the first three shipped in v11.0.0.

    Details
    • A generic subclass such as Response<T> broke document generation: subtype discovery returned open generic types, which can't have a schema of their own. It now skips them, and closed subtypes are still found.
    • A private or internal member marked [JsonProperty] crashed generation with Newtonsoft.Json. The maintainer pushed back on my first fix, which widened how members were found, so I narrowed it to the crash and added the snapshot test they asked for, and the PR was approved and merged.
    • A property declared as IReadOnlySet<T> was documented as a plain array, without the uniqueItems rule that ISet<T> gets. Merged within half an hour of opening. IImmutableSet<T> had the same gap, which I fixed in a follow-up, tested on .NET 11 and 10, and merged 14 minutes after opening.
    • A document filter that edited the document's Info was editing the configured one, so its changes piled up on every request. Each document now gets its own copy. The maintainer asked for two small changes, and merged it the same day.
    • Tests for both serializers and both inheritance options, with snapshots of the generated documents, on .NET 8, 9 and 10.
    C# · .NET · open source See #4245 → See #4244 → See #4246 → See #4272 → See #4273 →
  • System.IO.Abstractions

    Fixed a bug in System.IO.Abstractions, the .NET library for testing code that uses the file system: on Linux and macOS its mock file system named the root drive /:\ and listed it twice. Merged, and shipped the same day in v23.0.1.

    Details

  • TUnit

    Fixed a bug in TUnit, a testing framework for .NET: IsEquivalentTo could report an object as not equivalent to itself. Merged the same day, and shipped in v1.86.6.

    Details
    • The comparison never checked whether both sides were the same instance, so it read every member of one object twice. A getter that changes between reads, such as a counter or a clock, made the object differ from itself. Both comparison paths now return early for the same instance.
    • The same check fixed a false pass, where the cycle guard skipped an object it met for the second time. Tests for objects, collections and members, in both the source-generated and reflection modes, on .NET 10 and 11. The maintainer merged it about seven hours after I opened it.

  • Umbraco

    Fixed two bugs in Umbraco, the open-source .NET content management system: creating a multilingual document through its Management API without any language variants failed with a 500 instead of a 400, and adding a composition to a content type could leave the types built on it with two properties of the same alias. Both merged the day after I opened them, for versions 17.10, 18.5 and 19.1.

    Details
    • Validation let a document or blueprint of a language-varying type through with no variants, then the save failed, so the API returned a server error. Creating one now gets the same 400 that a type without languages gets, and updates can still leave the variants out. I agreed the approach with the maintainers on the issue first and fixed it on the long-term support branch, which they merge into the newer versions.
    • Tests for documents and blueprints that fail without the fix. The maintainer added a check for blank names and more tests on top, asked me to review them, then approved and merged it.
    • Adding a composition to a content type checked the new properties against that type's own, but not against the types built on it, so one of them could end up with two properties of the same alias. Those types are now checked too, and a clash stops the save with the same error as a clash on the type itself. A test that follows the steps in the issue fails without the fix, and 830 content, media and member type tests pass with it. Approved and merged the next day.

  • Authlib

    Fixed two bugs in how Authlib, a Python library for OAuth and OpenID Connect, renews expired tokens. Both merged.

    Details
    • Asking for a token with an explicit client_credentials grant never stored the grant, so once the token expired the next request failed instead of fetching a new one. The issue had been open since 2024.

  • Tornado

    Fixed two bugs in Tornado, the Python web framework and networking library, open since 2015 and 2021: a Vary header on responses that never vary, and WSGI apps failing on an unusual Host header. Both merged.

    Details
    • Gzip support added Vary: Accept-Encoding to every response, so caches kept a separate copy per encoding even of images it never compresses. It now adds the header only for types it may compress. The issue had been open since 2015.
    • The WSGI adapter split the Host header on : and read the rest as a port, so a header such as example.com:abc raised an error and the client got no response, and an IPv6 host came out wrong. It now uses Tornado's own host and port parser, with the extra tests a reviewer suggested.
    • Each case has a test that fails without the fix. The full suite passes on Python 3.12 and 3.14, and CI covers 3.11 to 3.15, free-threaded Python and PyPy.

My projects

  • grounded

    Answers questions from your own documents: every sentence cites the passage it came from, a local model checks that the passage really says it, and when the documents don't cover the question, it says so instead of guessing.

    Details
    • Each retrieved passage goes to Claude as its own document, so every part of the answer comes back with native citations to the passages it used, and nothing is parsed out of the prose. A small entailment model that runs on the CPU, nli-deberta-v3-small, then checks each sentence against the passages it cites, and the Next.js page marks it supported, not supported or uncited.
    • It refuses before calling the model when the best passage scores below 0.55. Both thresholds were measured on labelled data written before any code: on 47 questions, none of the 19 unanswerable ones got through and 2 of the 28 answerable ones were refused, and the checker's 0.70 judged 50 of 52 sentence and passage pairs correctly.
    • With Claude at medium effort, every sentence was cited, and every sentence the checker flagged was true when I read it against the documents, so a flag means "check this", not "wrong". 83 API tests, the store against real PostgreSQL, and 17 web tests. docker compose up runs it, with or without an API key.

  • hookline

    Delivers webhooks reliably, even when the receiver is down: each event is stored first, signed, retried with backoff, and set aside for a person to look at after the last attempt.

    Details
    • Workers share PostgreSQL with FOR UPDATE SKIP LOCKED and a lease, so any number can run without two sending the same delivery at once, and a worker that dies mid-send just lets its lease run out. Each keeps up to ten requests in flight, so a receiver that hangs holds up only its own delivery.
    • Every attempt is signed the Standard Webhooks way, checked against the reference library's fixed example. A 410 disables the subscription, Retry-After is honoured up to a cap, and redirects aren't followed. A Razor Pages dashboard shows each attempt and sends dead letters again.
    • 109 tests against real PostgreSQL and a real HTTP receiver, with a fake clock for the three-day retry schedule. I broke the worker 16 ways to check that the tests catch each break. docker compose up runs a receiver that fails, hangs and answers 410 on purpose.
    C# · ASP.NET Core · EF Core · PostgreSQL · Docker Run it yourself →
  • rotadesk

    Staff scheduling for small businesses: one app serving many of them, with each business's staff and shifts kept apart.

    Details
    • Managers build and publish the week, staff set when they can work and swap shifts, and everyone affected gets an email. The rules, such as no overlapping shifts, weekly hours limits and a swap that needs the colleague and a manager, live in one domain layer, so no endpoint can skip them.
    • Businesses share tables, kept apart four ways: an EF Core filter on every tenant-owned table, a guard on every write, a test that fails if a table has no filter, and a suite that calls every endpoint as the other business.     • Emails go through a transactional outbox, so a crash can't lose one. 242 .NET tests run against real PostgreSQL in Testcontainers, plus 77 front end tests, in CI on Linux, Windows and macOS. The live demo runs on Render and Neon, with one-click sign-in.

  • semcache

    Caches model answers by meaning rather than exact wording, and measures exactly where that goes wrong.

    Details
    • One decorator on an existing function. It checks the exact text first, never mixes answers between models or prompts, and if the cache fails the call still runs.
    • Stores in memory or in Redis 8 vector sets, where the search runs inside Redis. Both pass the same test suite, and their scores agree to within 0.000001.

  • llm-router

    One endpoint for many language models, with a spending cap that holds under concurrent load.

    Details
    • Speaks the OpenAI API, so an app adopts it by changing its base URL. Routes each request by policy and falls back when a provider fails: retries what can recover, skips a revoked key, and stops on a request every model would refuse.

AI Refinery

At SoftBuilds, since July 2026: the company's own product, a self-hosted LLM platform. Customers run open-source models on their own Kubernetes cluster, with no prompt leaving their network, and a cloud service on Azure supplies the model catalog and sells the plans. I designed and built the subscription enforcement that connects the two, and the billing and licensing around it.

How it runs

  • On the customer's side, one Helm chart installs the platform on Kubernetes. Traefik routes every request, and each model is served by llama.cpp as a KServe service on Knative, scaling to zero when idle.
  • In the cloud, FastAPI services on Azure Functions, PostgreSQL, and a React site on Azure Static Web Apps with Microsoft Entra ID sign-in.

Subscription enforcement

  • Each installation verifies a cloud-signed entitlement token itself, so enforcement keeps working with no internet. An hourly check re-reads the signed token rather than values in the local database, so editing the database unlocks nothing.
  • A locked installation refuses every model request and shows a lock screen, and a banner warns during the grace period before the cutoff. The cutoff is signed into the token, so it can't be extended locally, and access depends on the plan's status as well as its end date.
  • Notices a clock turned back, and recovers without internet once it's corrected. Air-gapped sites unlock by pasting a signed token.
  • Subscriptions and API tokens are scoped to their environment, so a sandbox payment can't unlock production.

Licensing

  • One plan, one system: each installation has a permanent ID, and claims are serialized in PostgreSQL with advisory locks and a partial unique index, so two machines can't share a plan.
  • Negotiated custom plans, from an admin's offer through checkout to per-feature and model-size limits enforced on the installation.

Billing

  • Moved billing from Stripe to Paddle, then added Stripe back behind one switch: signed webhooks, each event handled once, monthly and yearly plans, and a one-time trial.

Running it

  • Tested changes end to end on local k3d clusters, through Traefik to the models.
  • Traced a doubling of the Azure bill to model downloads streaming through one Function, after ruling out storage, egress and logging, and traced a model-sync failure across both services to a rejected API key.
